# Как построить Segmented Control с нуля — подробный план (без готового кода)

Документ описывает только *что* и *в каком порядке* делать. Код внутри —
только маленькие подсказки-паттерны (не решение), чтобы дописать самому.

---

## Этап 0. Подготовка

Раздели задачу на 3 независимых слоя, которые почти не пересекаются:
1. **Геометрия** (позиции/размеры слайдера) — чистая математика.
2. **Визуал заливки текста** (маска + инверт-слой) — CSS + чуть JS.
3. **Анимация переходов** (в т.ч. раскрытие 3-го состояния) — anime.js/JS.

Не пытайся писать всё сразу. Каждый этап ниже должен быть *визуально
проверяем* прежде чем переходить к следующему.

---

## Этап 1. Капсула и статичный слайдер (0 анимаций, 2 позиции)

Цель: слайдер стоит либо слева, либо справа, без движения — просто по клику
резко телепортируется.

Что нужно:
- Контейнер `position: relative`, `border-radius: 9999px`, `padding` (это
  важно — паддинг капсулы = отступ слайдера от края, запомни это число, оно
  понадобится в математике).
- Внутри — слой с двумя кликабельными зонами (обычные `<label>` с `<input
  type="radio">` внутри — так у тебя будет доступность и работоспособность
  без единой строчки JS в базовом виде).
- Отдельный `div` для слайдера — `position: absolute`, ширина ровно 50% минус
  паддинги с двух сторон (подумай, почему не просто `50%`).

Проверка: клик по любому option должен через JS выставлять `style.left` и
`style.width` слайдера напрямую (`element.style.left = ... + 'px'`), без
анимации — просто прыжок. На этом этапе не думай про плавность.

Вопрос самому себе перед переходом дальше: если я сделаю `width: 33%`, как
изменится формула для `left` второго элемента? Если легко ответишь — этап
пройден.

---

## Этап 2. Функция позиции — абстрагируй геометрию

Не хардкодь `left`/`width` в обработчике клика. Вынеси в отдельную функцию,
принимающую "куда хотим встать" (строка-идентификатор состояния), которая
возвращает объект с `left` и `width` в пикселях.

Важно измерять **реальную ширину контейнера** через `getBoundingClientRect()`,
а не полагаться на проценты в JS — потому что дальше тебе нужно будет делить
эту ширину на 2 и на 4, и удобнее работать с абсолютными пикселями, чем с CSS
percentage strings.

Проверка: если ты меняешь ширину окна браузера (или капсулы через
media-query), а потом кликаешь — слайдер должен вставать в верно
пересчитанное место. Если нет — где-то закэширован старый размер.

---

## Этап 3. Плавность через CSS transition (временное решение)

Прежде чем тащить анимационную библиотеку, добавь простой
`transition: left .3s, width .3s` в CSS слайдера. Это самый дешёвый способ
проверить, что твоя геометрия (Этап 2) работает правильно — если transition
плавно доезжает до правильной позиции при любом клике, логика позиции верна.

Это временный костыль, ты его выкинешь на Этапе 6, когда подключишь
anime.js — но он полезен как чек-пойнт для отладки без сложностей таймингов
библиотеки.

---

## Этап 4. Инвертированный текст — самая концептуально сложная часть

Идея: у тебя должен быть **второй, полностью идентичный набор текста**,
который лежит поверх первого, но:
- виден только в узком окне (там, где сейчас слайдер),
- имеет другой цвет (контрастный фону слайдера).

Как это устроить пошагово:

1. Продублируй весь блок с подписями (текст) — сделай второй такой же набор
   элементов рядом (не внутри первого, а параллельно).
2. Оберни этот второй набор в контейнер с `overflow: hidden` — назови его,
   скажем, "окно". Это окно должно иметь **точно ту же позицию и ширину**,
   что и слайдер (используй ту же функцию из Этапа 2).
3. Задача: сделать так, чтобы текст внутри окна визуально совпадал по
   расположению букв с оригинальным текстом снаружи — как будто это один и
   тот же текст, просто увиденный через маленькое окошко другого цвета.

Как этого добиться: внутренний дублированный блок должен быть **шире, чем
окно** (равен ширине всей капсулы), и сдвинут через `left` в направлении,
противоположном смещению окна. То есть если окно сдвинуто вправо на X px,
внутренний текст должен быть сдвинут влево на те же X px относительно окна —
тогда в статичной системе координат буквы окажутся ровно там же, где и
оригинал.

Подсказка-формула (не копируй бездумно, выведи сам и сверь):
```
сдвиг_внутреннего_текста = -(позиция_окна - паддинг_капсулы)
```
Попробуй вывести, почему тут вычитается именно паддинг, а не 0.

Проверка: включи в DevTools временный `outline: 1px solid red` на обоих
текстовых блоках (оригинал и инверт) и подвигай окно вручную (меняя left в
DevTools) — буквы должны идеально совпадать по X-координате в любой позиции
окна.

Порядок слоёв (z-index) сверху вниз обязателен:
1. окно с инверт-текстом (самое верхнее)
2. обычный текст
3. сам слайдер (самый нижний, просто цветной фон)

Если перепутаешь порядок — увидишь либо белый текст на белом фоне, либо
слайдер перекроет весь текст целиком.

---

## Этап 5. Убедись что клики идут туда, куда нужно

У тебя теперь 3 слоя друг на друге. Инвертированный текстовый слой не должен
перехватывать клики — у него нет интерактивных элементов (не добавляй туда
`<input>`), только визуальное дублирование. Все клики обрабатываются
исключительно оригинальным (нижним по смыслу, но не по z-index) слоем текста.

Проверка: кликни ровно по центру капсулы (где сейчас слайдер) и по краям —
переключение должно работать одинаково в обеих зонах.

---

## Этап 6. Подключи anime.js вместо CSS-transition

Убери CSS `transition`. Теперь движение слайдера, окна-маски и
инверт-текста должно управляться через анимационную библиотеку, тремя
отдельными вызовами, но:
- с одинаковой длительностью и одинаковой кривой (easing) для всех трёх —
  иначе слайдер и окно/текст разъедутся в середине движения и ты увидишь
  "отставание" текста от заливки.
- **обязательно отменяй предыдущую анимацию** перед стартом новой для тех же
  целевых элементов (в anime.js есть метод для этого) — иначе быстрые
  повторные клики создадут очередь и слайдер будет дёргаться туда-сюда после
  серии кликов.

Проверка: покликай очень быстро между двумя состояниями подряд 5-10 раз —
слайдер должен всегда ехать к последней выбранной позиции без "дребезга".

---

## Этап 7. Раздели рендер "с анимацией" и "без анимации"

Тебе понадобится версия функции движения слайдера с флагом:
можно/нельзя анимировать. Без анимации (мгновенно) она нужна для:
- первой отрисовки страницы (не должно быть "наезда" анимации на загрузку),
- пересчёта позиции при изменении размеров окна/капсулы (ResizeObserver).

С анимацией — для реакции на клик пользователя.

---

## Этап 8. Третье состояние — раскрывающийся под-выбор

Теперь усложнение: один из двух видимых пунктов при клике должен
"раскрываться" в два дочерних варианта.

1. Внутри этого пункта сделай **два слоя друг на друге** (оба
   `position: absolute`, занимают всю зону пункта): один — просто текст
   ("свёрнутое" состояние), второй — два под-варианта рядом + тонкий
   разделитель между ними (изначально невидимый, `opacity: 0`).
2. Функция позиции слайдера (Этап 2) должна получить третий и четвёртый
   вариант расчёта: пункт, который раньше занимал половину капсулы, теперь
   должен уметь делиться на две четверти — подумай, как переиспользовать уже
   посчитанные halfWidth/quarterWidth, а не писать позиции заново с нуля.

---

## Этап 9. Анимация раскрытия — это НЕ одна анимация, а несколько параллельных

Раскрытие должно выглядеть как согласованное, но не синхронное по таймингу
событие. Раздели его на независимые анимации с разной длительностью:
- исчезновение свёрнутого текста — короче по времени,
- появление под-вариантов — чуть дольше (не должно быть паузы-провала между
  исчезновением первого и полным появлением второго — специально сделай
  появление длиннее исчезновения, чтобы они внахлёст),
- появление разделителя — отдельно, тоже через opacity,
- и отдельно (но с тем же easing, что в Этапе 6) — движение самого слайдера
  к новой (более узкой) позиции.

Схлопывание (обратный переход) должно быть зеркальным, но не идентичным по
таймингу: попробуй сначала спрятать разделённые варианты (быстро), затем
показать свёрнутый текст (медленнее) — так избежишь визуального наложения
двух текстов друг на друга в середине перехода.

Отключай `pointer-events` на скрытом слое именно в момент старта
соответствующей анимации (не заранее и не постфактум) — иначе можно словить
клик по невидимому, но ещё кликабельному элементу, либо наоборот пропустить
клик по уже видимому.

---

## Этап 10. Разбитие клика по половине текста

Свёрнутый текст (третий пункт до раскрытия) должен уметь по одному клику
сразу понять, какой из двух под-вариантов выбрать — в зависимости от того, по
какой половине текста кликнули (левой или правой). Для этого в обработчике
клика нужно получить координату клика относительно самого элемента (через
`getBoundingClientRect` и `event.clientX`) и сравнить её с половиной ширины
элемента.

---

## Этап 11. Состояние как единственный источник истины

Заведи одну переменную состояния (строку с текущим выбранным вариантом) и
один производный флаг ("раскрыто" ли третье состояние). Все остальные части
системы (позиция слайдера, какой слой видим, значение radio-инпута,
localStorage) должны **вычисляться из этой переменной**, а не жить
независимо — иначе куски интерфейса начнут рассинхронизироваться при
быстром взаимодействии.

Разработай отдельную функцию "применить текущее состояние" (без анимации),
которая используется только при первой загрузке страницы и при ресайзе, и
не путай её с функциями анимированного перехода, которые вызываются по
кликам.

---

## Этап 12. Персистентность и синхронизация с radio

- Сохраняй состояние в `localStorage` при каждом изменении.
- При загрузке — читай оттуда, а не всегда начинай с состояния по умолчанию.
- Синхронизируй скрытый `<input type="radio">` с текущим состоянием (ставь
  `checked` на нужный) — это нужно, если компонент используется как часть
  формы, и просто для консистентности DOM с визуалом.

---

## Этап 13. Отзывчивость на resize

Подключи наблюдатель за изменением размеров контейнера (`ResizeObserver`) и
на каждое изменение — пересчитывай позицию слайдера **без анимации** (версия
функции из Этапа 7), иначе при ресайзе браузера слайдер будет дёргано
"доезжать" через анимацию каждый раз, что выглядит некрасиво.

Не забудь на каждом пересчёте также обновлять ширину внутреннего
инверт-текстового блока (Этап 4) — она должна совпадать с шириной блока
подписей, а при ресайзе капсулы обе ширины меняются.

---

## Этап 14. Темизация (опционально, отдельно от логики)

Вынеси все цвета в CSS-переменные, определи несколько наборов значений через
атрибут на `<html>` (например `data-theme`). Переключение темы — это только
смена атрибута, JS-логика слайдера при этом не должна знать о темах вообще
(она оперирует только числами: left, width). Так ты держишь визуальный слой
(цвета) полностью отдельно от геометрического слоя (позиции).

---

## Порядок самопроверки в конце

Пройди по чек-листу, кликая руками:
1. Клик по первому пункту из раскрытого состояния — плавно схлопывается.
2. Клик по левой/правой половине свёрнутого текста — раскрывается сразу в
   нужный под-вариант.
3. Клик между двумя под-вариантами — слайдер плавно едет между четвертями.
4. Быстрая серия кликов подряд — без дёргания/тиков.
5. Перезагрузка страницы — состояние восстановилось, анимации при этом не
   было видно (не мигнуло).
6. Изменение размера окна — слайдер и текстовая маска остаются на месте
   (не съезжают).
7. Смена темы — не влияет на позицию/анимацию, только на цвета.

Если весь список проходит — компонент готов.
