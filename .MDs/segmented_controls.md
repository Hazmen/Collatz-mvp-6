# Устройство Segmented Control (3 состояния, вложенный auto/manual)

## 1. Идея в целом

Компонент — это переключатель на 2 видимых слота ("Мгновенный" / "Step By Step"),
но второй слот при клике **раскрывается** в два под-варианта (Auto / Manual).
Итого 3 реальных состояния: `instant`, `auto`, `manual`, но визуально это выглядит
как один плавно трансформирующийся элемент, а не как список из 3 кнопок.

Ключевая техника, на которой всё держится: **два перекрывающихся набора текста**
(обычный и инвертированный по цвету) + **белый слайдер поверх**, который через
маску показывает инвертированный текст только там, где он сам находится. Это
даёт эффект "заливки" текста цветом слайдера без анимации `color` (анимация
цвета дорогая и дёргано выглядит на прозрачности/градиентах).

## 2. Слоёная структура (z-index снизу вверх)

```
.segmented-control (капсула, position: relative)
 ├─ .slider           — белый/цветной прямоугольник, z-index: 1
 ├─ .labels           — обычные подписи (не залитые), z-index: 2
 └─ .clip-mask        — окно overflow:hidden, z-index: 3
     └─ .labels-invert — те же подписи, но цвет инвертирован
```

`.clip-mask` имеет **точно такие же left/width**, как `.slider` (тот же
`getSliderPos()`), и `overflow: hidden`. Внутри него лежит `.labels-invert` —
полная копия текста шириной во весь контрол, сдвинутая через `left` в
противоположную сторону (`-(pos.left - padding)`), чтобы буквы совпадали
пиксель-в-пиксель с `.labels`.

Итог: под слайдером (в зоне clip-mask) видно инвертированный текст, вне
слайдера — обычный текст. Двигая `.slider` и `.clip-mask` синхронно одной и
той же позицией, получаем "заливающийся" текст без анимации цвета.

Это классический приём "text mask slider", используется в iOS-подобных
переключателях.

---

## 3. Разметка: два набора текста — зачем дублировать

```html
<div class="labels">      <!-- обычный цвет -->
  <label class="option" data-value="instant">...</label>
  <div class="sbs-wrapper">...</div>
</div>

<div class="clip-mask">
  <div class="labels-invert">  <!-- инвертированный цвет, БЕЗ input -->
    <label class="option" data-value="instant">...</label>
    <div class="sbs-wrapper">...</div>
  </div>
</div>
```

`.labels-invert` — визуальный дубликат без `<input>`: клики не нужны, за них
отвечает верхний `.labels`. У `.labels-invert .option` стоит `cursor: default`
и нет `<input>` — этот регион и так уже выбран (он показывается только внутри
зоны слайдера).

---

## 4. sbs-wrapper: single ⇄ split

Внутри второго слота лежит `.sbs-wrapper` с двумя абсолютно позиционированными
слоями друг на друге:

```html
<div class="sbs-wrapper">
  <div class="sbs-single">Step By Step</div>   <!-- показан по умолчанию -->
  <div class="sbs-split">                       <!-- скрыт, opacity:0 -->
    <label class="option" data-value="auto">Auto</label>
    <div class="divider"></div>
    <label class="option" data-value="manual">Manual</label>
  </div>
</div>
```

Оба `position: absolute; inset: 0`, лежат друг на друге. Переключение между
ними — не display:none/block, а **opacity + scale через anime.js**, чтобы был
плавный кросс-фейд, а не резкая замена. `will-change: transform, opacity`
подсказывает браузеру заранее подготовить слой (GPU-композиция).

`.divider` — вертикальная палочка между Auto/Manual, тоже анимируется через
opacity (0 → 1), имитируя "появление" разделителя одновременно с раскрытием.

## 5. Математика позиции слайдера — `getSliderPos()`

```js
function getSliderPos(target) {
    const innerWidth = controlRect.width - padding * 2; // капсула минус паддинги
    const halfWidth = innerWidth / 2;
    const quarterWidth = innerWidth / 4;

    if (target === 'instant') return { left: padding, width: halfWidth };
    if (target === 'auto')    return { left: padding + halfWidth, width: quarterWidth };
    return { left: padding + halfWidth + quarterWidth, width: quarterWidth }; // manual
}
```

Схема капсулы (padding = 5px по краям):

```
| instant (50%) | auto (25%) | manual (25%) |
```

`instant` занимает всю левую половину. Второй слот (тоже половина) при
раскрытии виртуально делится на 2 равные четверти — слайдер просто сужается
вдвое и смещается вправо, оставаясь внутри той же половины.

Именно поэтому переход `instant → auto` выглядит целостно: слайдер не
"прыгает" на новую дорожку, а сначала занимает всю правую половину (при клике
по sbs-single ещё до разделения), потом сужается до четверти в момент
`expandSBS`.

## 6. Синхронное движение трёх слоёв — `moveSliderTo()`

```js
function moveSliderTo(pos, animate) {
    syncInvertWidth();                         // labels-invert = ширине labels
    const invertLeft = -(pos.left - padding);  // зеркальный сдвиг

    anime.remove([slider, clipMask, labelsInvert]); // отменить текущие твины

    anime({ targets: [slider, clipMask], left: pos.left, width: pos.width,
             duration: 420, easing: 'cubicBezier(0.16, 1, 0.3, 1)' });

    anime({ targets: labelsInvert, left: invertLeft,
             duration: 420, easing: 'cubicBezier(0.16, 1, 0.3, 1)' });
}
```

Три анимации с **одинаковыми duration и easing**, чтобы визуально это была
одна фигура. `anime.remove(...)` перед стартом — критично: без него быстрые
повторные клики создают очередь твинов и слайдер "дёргается"/скачет назад.

`cubicBezier(0.16, 1, 0.3, 1)` — easing типа ease-out-expo, даёт резкий
старт и мягкое затухание — характерное ощущение iOS-анимаций.

## 7. Раскрытие/схлопывание — `expandSBS()` / `collapseSBS()`

Это отдельные, более богатые анимации (не просто `applyState`), потому что
раскрытие — это составное событие: одновременно происходит

1. исчезновение `sbs-single` (scale 1→0.85, opacity 1→0, 220ms)
2. появление `sbs-split` (opacity 0→1, scale 0.95→1, 320ms — длиннее, чтобы
   не было "дыры" между исчезновением одного и появлением другого)
3. появление `divider` (opacity, 300ms)
4. движение слайдера в новую позицию (общий `moveSliderTo`)

Отдельные `duration` для каждого слоя — не случайность, а способ избежать
эффекта "все элементы дёргаются одновременно как один блок". Реальные UI
анимации почти всегда имеют разный тайминг для разных слоёв (stagger).

`collapseSBS()` — зеркальная последовательность, но в другом порядке
(сначала split исчезает быстрее — 180ms, потом single появляется — 320ms),
чтобы не было наложения двух текстов друг на друга в момент перехода.

`pointer-events` переключаются в `begin` колбэках анимации — то есть клики
на скрытый слой отключаются не мгновенно по CSS-классу, а именно в момент
старта соответствующей анимации.

## 8. Состояние и его источник истины

```js
let state = localStorage.getItem('segmented-mode') || 'instant';
let expanded = state === 'auto' || state === 'manual';
```

- `state` — строка `'instant' | 'auto' | 'manual'`, единственный источник
  истины для позиции слайдера.
- `expanded` — производный флаг: показывать sbs-single или sbs-split.
- `syncRadio()` синхронизирует скрытый `<input type="radio">` с `state`
  (нужно для форм / доступности / сохранения в localStorage при перезагрузке).
- При загрузке страницы состояние восстанавливается без анимации
  (`applyState(false)` / `expandSBS(state, false)`), чтобы не было "вспышки"
  анимации при первом рендере.

## 9. Хронология: как строить такое с нуля

### Шаг 1 — статичная капсула с 2 слотами (без анимаций)
- `.segmented-control` — flex/relative контейнер, `border-radius: 9999px`.
- `.labels` — 2 `<label>` с `<input type="radio">` внутри (для доступности и
  чтобы работало без JS в фолбэк-режиме).
- `.slider` — `position: absolute`, ширина 50%, просто лежит слева.
- Проверить, что визуально капсула выглядит как обычный toggle на 2 пункта.

### Шаг 2 — слайдер двигается по клику (без анимации библиотекой)
- Обработчик клика на `.option` меняет `slider.style.left/width` напрямую.
- `getSliderPos()` пока только для 2 позиций (0% / 50%).
- Добавить `transition: left 0.3s, width 0.3s` в CSS как самый простой вариант
  анимации (до внедрения anime.js).

### Шаг 3 — залитый (инвертированный) текст поверх слайдера
- Продублировать `.labels` → `.labels-invert`, обернуть в `.clip-mask` с
  `overflow: hidden` и теми же координатами, что у `.slider`.
- Сдвигать `.labels-invert` на `-left` относительно `.clip-mask`, чтобы текст
  совпадал с оригиналом. Это самая концептуально сложная часть — стоит
  проверять на глаз через DevTools, включив `outline` на обоих слоях.
- Убедиться, что цвет текста в `.labels-invert` через CSS-переменную
  `--text-invert` контрастен цвету `.slider`.

### Шаг 4 — переход на anime.js вместо CSS-transition
- Убрать CSS `transition`, подключить anime.js.
- Написать `moveSliderTo(pos, animate)`, где `animate=false` — мгновенная
  установка (для первого рендера/ресайза), `animate=true` — твин.
- Добавить `anime.remove(targets)` перед каждым новым твином, чтобы избежать
  очереди анимаций при быстрых кликах.

### Шаг 5 — третье состояние: sbs-wrapper с single/split
- Добавить внутрь второго слота `.sbs-wrapper` с двумя абсолютными слоями
  (`.sbs-single`, `.sbs-split`), `.sbs-split` изначально `opacity: 0`.
- Задать `getSliderPos()` третий вариант — деление половины на 2 четверти.
- Функции `expandSBS(target)` / `collapseSBS()` — отдельно от простого
  двухпозиционного переключения, со своей последовательностью opacity/scale.

### Шаг 6 — определение клика по половине текста
```js
sbsSingle.addEventListener('click', (e) => {
    const rect = sbsSingle.getBoundingClientRect();
    const x = e.clientX - rect.left;
    const target = x < rect.width / 2 ? 'auto' : 'manual';
    expandSBS(target, true);
});
```
Это позволяет одним кликом по надписи "Step By Step" сразу выбрать нужный
под-вариант в зависимости от того, по какой половине текста кликнули.

### Шаг 7 — разделитель между Auto/Manual
- `.divider` — узкая полоска, `opacity: 0` по умолчанию, анимируется вместе
  с `expandSBS`/`collapseSBS`.

### Шаг 8 — синхронизация ширины invert-слоя при ресайзе
- `ResizeObserver` на `.segmented-control`, при изменении размеров
  пересчитывает позицию без анимации (`moveSliderTo(pos, false)`).
- `syncInvertWidth()` перед каждым движением подгоняет ширину
  `.labels-invert` под текущую ширину `.labels` (на случай адаптивных
  media-query, где капсула меняет размер).

### Шаг 9 — персистентность состояния
- `localStorage.getItem/setItem('segmented-mode')`.
- Скрытые `<input type="radio">` синхронизируются через `syncRadio()` —
  нужно, если компонент используется внутри `<form>`.

### Шаг 10 — темизация через CSS-переменные
- Все цвета вынесены в `:root` и `[data-theme="..."]` блоки.
- Смена темы — просто `setAttribute('data-theme', ...)` на `<html>`,
  ничего в JS-логике слайдера трогать не нужно, т.к. он оперирует только
  геометрией (`left/width`), а не цветом напрямую.

## 10. Итоговые принципы

1. **Не анимируй `color`** для заливки текста — используй маску + слой с
   инвертированным цветом, двигай геометрию, а не палитру.
2. **Синхронизируй несколько анимаций одинаковым duration/easing**, если они
   должны восприниматься как единое целое (слайдер + маска + инверт-текст).
3. **Разные тайминги для разных смысловых слоёв** (single/split/divider) —
   так анимация не выглядит "one blob moving", а выглядит "продуманной".
4. **`anime.remove()` перед каждым новым твином** — обязательная защита от
   гонки анимаций при частых кликах.
5. **Состояние (state) как единственный источник истины**, из которого
   выводятся: позиция слайдера, `expanded`-флаг, значение radio, localStorage.
6. **Мгновенный рендер при инициализации** (`animate=false`) — анимации нужны
   только для реакции на действие пользователя, не для первой загрузки.
